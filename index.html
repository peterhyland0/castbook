Did the chained workflow keep the character?

Castbook chains open-weights models (keyframe → video → stitch) on Modal GPUs, scores every shot against the character's face, re-rolls the shots that drift, and records what each step cost. Workflows are versioned configs, so two recipes can be run on the same script and compared on identity, retries and dollars per accepted second of video.

A number you can trust, and knowing when you can't

The first run scored every frame and got a clip mean of 0.33, min 0.01: it looked like the face drifted. It mostly hadn't. She turns toward a window, and ArcFace collapses on profiles even for the right person. The judge now leaves out frames turned past 45°, frames with a hand over the face, and faces under 64 px, and returns pass, fail or unverifiable instead of a misleading low score.

Fix it at the cheap step

Shot 1's face was 79 px wide in the keyframe, about 53 px in the 480p clip, so every frame was unverifiable. Rendering clips at 720p made it measurable, but at 3.6× the clip cost. The framing check predicts the clip's face size from the keyframe and re-frames the keyframe instead, for about $0.003.

How it works

  1. Character: one portrait → ArcFace embedding.
  2. Keyframes: Qwen-Image-Edit-2511 composes each shot's start (and end) still from the portrait. Gated: identity, plus a face-size and camera-direction check, re-rolled or re-prompted by cause.
  3. Clips: Wan 2.2 I2V A14B animates between keyframes. Gated the same way.
  4. Stitch: ffmpeg concat. One failed shot degrades the run; it doesn't fail it.
  5. Every step is content-addressed: sha256(step, model@rev, params, inputs, seed). A re-run or a new workflow version only computes what changed, so A/B arms share upstream work.
  6. On Modal: one GPU class per model family, weights on a Volume, a CPU orchestrator and a FastAPI layer that scale on their own. 106 unit tests run in CI without a GPU.

Warm inference is already cheap and fast; the cost is the cold start. Wan's weights take over three minutes to load and cast, so most of a small run's bill is model loading. Re-saved bf16 weights plus Modal memory snapshots are the next step.

What's next

  • Six shots, one API call. A 30-second script through the API to a stitched video and a run page.
  • Retry ladder as config: same → degrade → alternate model → fallback shot, so an agent's retry rules become testable code with bounded cost.
  • Calibration: fit the identity threshold to face size on hand-labeled frames, and use the gate to measure how often an LLM critic agrees with it.
  • Cold starts: bf16 weights and memory snapshots, with a before/after table.
  • More arms: full-step vs 4-step Wan, and hosted video APIs behind the same adapter interface.
