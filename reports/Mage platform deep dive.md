# Build the identity-gated pipeline Mage lacks

Mage (mage.space, run by Ollano, Inc. in NYC) is now a multi-model image, video and audio studio built around one primitive: a reusable **Character**. A user saves one portrait under an `@handle`, and about **30 image and video models** accept it. Those models include Mage's own white-labeled "fruit" models, open weights it serves on its own GPUs (Flux 2, Wan 2.2, LTX, Z-Image and others), and third-party APIs (GPT Image, Grok, Nano Banana, ElevenLabs). Characters launched on Jan 9, 2026. Almost every release since has either extended the character (voices, motion control, multi-character scenes, swap apps) or chained it through multi-step tools (Storyboard, Story Studio, Autocreate, Mage Agent, Projects). On Sep 26, 2026, Mage opened all of this to developers through an async REST API, an MCP server and SDKs. The company has about nine people and claims 1.4M MAU, roughly 30% month-over-month growth and profitability. Its web traffic roughly quadrupled in a year. Competitors such as Kling, Runway, Google Flow, OpenArt, Higgsfield, Krea and LTX have converged on the same "@-mention a saved character" pattern, and on agents that build node graphs. None of them checks whether the output actually matches the character, compares workflow variants against each other, or retries when quality is poor. Those gaps are your best opening. The project that best shows fit is **a FastAPI-on-Modal "character → shots → video" pipeline service**. Every shot passes an ArcFace identity gate with bounded auto-retry. Workflows are immutable, versioned DAG configs that can be A/B-tested on identity score, cost and latency. Artifacts are content-addressed, so variants share upstream work. Moderation sits at three gates, and adding a new open-weights model or third-party API is a small adapter plus a CI eval. That project covers nearly every line of the JD. It also matches the work the CEO described: chaining workflows into videos and testing variants.

## Mage organized 2026 around a face that travels across 30 models

The Character feature is simpler than the marketing suggests. To create one, a user uploads a single clear, front-facing portrait and names it, and the docs say it is then "available on every supported model". The docs mention no LoRA training. The mechanism is reference-image conditioning, and **each model caps how many references it takes**: 3 for Grok Image and Guava, 10 for Mango, 14 for Nano Banana, 15 for GPT Image, and **50 for the flagship Cherry 2 Pro video model** ([Mage docs: Characters](https://docs.mage.space/features/characters)). Characters control **face only**. Outfit, pose and location come from separate saved "References", and the docs warn that one portrait gives a reliable face but unreliable full-body proportions. One constraint matters for pipeline design: on Berry, Lemon, Melon, MiniMax-H3 and Plum, **Character references and First/Last Frames are mutually exclusive** in a single generation ([Mage docs: Characters](https://docs.mage.space/features/characters)). On those models you can lock the identity or lock the shot boundaries, but not both.

The release timeline shows how quickly the feature became the product. Characters launched on **Jan 9, 2026, working only with Mango V2** ([Mage blog](https://blog.mage.space/article/new-create-use-characters/674f8c62-d68c-4d2d-908d-c9fc01ad0b62)). Storyboard followed on Jan 13. Then came Multi-Characters (Jan 24), public Character pages and a leaderboard (Jan 30 and Feb 5), Character Motion Control via the "Pear" model (Feb 11), References (Mar 5), and a wave of single-purpose Apps for swaps, inpainting and enhancing (Mar 20–27) ([Mage blog index](https://blog.mage.space/)). Character Voices and Scene Builder arrived on May 15, so a character keeps one voice wherever it speaks ([Mage docs: Character Voices](https://docs.mage.space/features/character-voices)). Story Studio (Jun 12) turns one prompt into **5–20 connected scenes with up to 3 Characters**. Its own docs admit that consistency "is less reliable over long sequences" and suggest generating key scenes individually ([Mage docs: Storyboard/Story Studio/Autocreate](https://docs.mage.space/features/storyboard-story-studio-autocreate.md)). That admission is a direct pointer to the problem a side project can solve.

The consumer app has no visual node editor. Chaining happens through three things: persistent assets, media-in Apps that work as de facto pipeline steps (Video Editor, Video Character Swap, Lipsync, Music Video), and the conversational **Mage Agent (beta, Sep 2026)**. Agent pairs with **Projects** (Sep 26), which store a project's Characters, References, creative instructions and default model settings, so "Agent starts each session with the same context" ([Mage blog: Mage Agent](https://www.mage.space/blog/mage-agent); [Mage blog: API, MCP & Projects](https://www.mage.space/blog/mage-api-mcp-projects)). For developers there are open-source agent **Skills** that package multi-model pipelines. Examples are `/mage-ugc-video` (product → creator-style video with a scripted hook and spoken lines) and `/mage-faceless-video` (topic → researched, narrated video). They sit on MCP tools named `list_models`, `estimate_cost`, `generate`, `get_request` and `create_upload` ([Mage docs: Skills](https://docs.mage.space/api/integrations/skills.md)). There are also ComfyUI nodes that call Mage models remotely ([Mage docs index](https://docs.mage.space/llms.txt)).

Higher resolution, longer duration, extra references, Fast Mode (a paid priority queue advertised as "5–15× faster") and API calls all cost Gems, and **failed generations refund Gems** ([Mage docs: Models overview](https://docs.mage.space/models/overview.md); [Mage pricing](https://www.mage.space/pricing)). In February 2026 Mage raised Pro from $25 to $30 and Pro Plus from $50 to $60, and added the $200 Max tier. GPU cost per generation is therefore directly a margin problem. The public API launched in beta on Sep 26, 2026, with Python and TypeScript SDKs on Oct 2. It lives at `api.mage.space/v1` and uses per-model endpoints (`/v1/flux2/generate`). Calls are async: a submit returns `request_id`, `status_url` and `cancel_url`, and the client polls, since the docs describe no webhooks. Responses carry an `architecture` field and a `billing` block. The SDKs send **idempotency keys so retries don't double-charge**, and Characters and References are first-class API resources ([Mage docs: API overview](https://docs.mage.space/api/overview); [Mage docs index](https://docs.mage.space/llms.txt)). A side project should copy this API shape.

Moderation is load-bearing. Mature content is allowed through a user toggle. Creating a Character from a non-consenting real person's photo, or cloning their voice, is prohibited ([Mage docs: Content rules](https://docs.mage.space/policy/content-rules.md)). Trustpilot rates Mage **2.4/5 across 32 reviews**. The complaints cluster on over-blocking (one user's own AI creations were flagged as "real people"), sudden bans, confusing "unlimited vs Gems" billing, and credits spent on unusable outputs, with one user estimating about 10 usable images out of 134 ([Trustpilot](https://www.trustpilot.com/review/mage.space)). Two of those complaints are infrastructure problems: false positives in the moderation stage, and paying for outputs nobody checked.

## Competitors made characters table stakes but never verify them

By late 2026 almost every platform has a reusable character, built in one of three ways. The first is **zero-training reference elements**. Kling Elements take 1–4 images or a 3–8 s video clip, with optional voice binding from 5–30 s of audio, and allow up to 7 references per video generation ([Kling Element Library guide](https://kling.ai/quickstart/klingai-element-library-3-user-guide)). Runway does the same with References, Google Flow with Veo 3.1 "Ingredients" ([Google blog](https://blog.google/innovation-and-ai/technology/ai/veo-3-1-ingredients-to-video/)), and OpenArt with Character 2.0 from one image ([OpenArt What's New](https://openart.ai/whats-new)). LTX and Mage also take this approach. The second is **fast per-person fine-tunes**. Higgsfield Soul ID trains on 20–80 photos in "a few minutes", and the result "isn't exportable as a standalone file" ([Higgsfield Help Center](https://higgsfield.ai/creator-hub/help-center/ai-models/how-do-i-create-and-use-a-soul-id-character)). Leonardo, Civitai and SeaArt offer LoRA training. The third is **video- and voice-bound identities**, as in Kling 3.0 Omni and Hedra. In every case the identity is locked to one platform and usually to a subset of its models. Mage's edge is breadth: one portrait works on about 30 models, including other labs'. The industry is also moving from face-only identity toward bundles of face, outfit, voice and motion, which Mage partly matches with Voices and Pear.

Chaining has converged on a three-layer stack. Power users get node canvases: Runway Workflows (Oct 2025), Krea Nodes, Freepik Spaces, Figma Weave and Comfy Cloud. End users get graphs published as apps. On top sits **an agent that writes and runs the graph from chat**, the dominant 2026 pattern. Krea launched Prompt-to-Workflow on Feb 10, 2026, Runway's Agent began building and running full Workflows on Jul 23, 2026, Glif 2.0 launched on Apr 23, 2026, and ComfyUI added an agent in October 2026 ([Krea Nodes docs](https://www.krea.ai/docs/user-guide/features/nodes); [Runway changelog](https://runway.com/changelog); [Glif changelog](https://glif.app/changelog/2026-04-23-glif-v2-launch); [Digital Production](https://digitalproduction.com/2026/10/09/comfy-agent-ai-comfyui-workflows/)). Cost transparency has improved. Krea's Node Agent **shows a per-node cost breakdown before anything runs** and reruns only downstream nodes after an edit. Runway added Model Routers that pick a video model by cost, latency or quality (Jul 21, 2026), opt-in capacity fallbacks and a Task Cost API (Jul 30), and cheap 480p Seedance draft modes (Oct 2) ([Runway changelog](https://runway.com/changelog)).

Failure handling stays shallow everywhere. The changelogs and docs cover auto-fixed graph connections, capacity fallbacks and credit caps, and **nobody documents a check on output quality**. No platform says it scores identity drift and re-rolls the shot. Users feel this as the cost of checking by eye. Re-roll cycles burn credits ([aivideos.eu](https://aivideos.eu/blog/stop-wasting-ai-video-credits)), and drift builds up across clips because most video models generate each clip without memory of earlier shots ([Magic Hour](https://magichour.ai/blog/how-to-keep-characters-consistent-in-ai-video)). The measurement tools are open and standard. VBench-2.0 scores identity with RetinaFace detection plus ArcFace embeddings across frames ([VBench-2.0](https://arxiv.org/html/2503.21755v1)), and research papers report FaceSim-Arc, the cosine similarity of ArcFace embeddings between reference and generated frames ([Concat-ID](https://arxiv.org/pdf/2503.14151)). This gap rests only on absence from public docs, and a platform could score identity internally without saying so. A node canvas or a chat-to-video agent would still be a poor side project: both markets are crowded, and well-funded companies are already in them.

## The 2026 reference pipeline anchors identity in keyframes, not prompts

The research on long-form generation agrees on one point: **consistency comes from passing typed conditioning artifacts between shots, not from repeating text prompts**. MVAgent (Sep 2026) points out that when each shot is a separate request to a frozen generator, repeated text does not fix appearance or state. Its agents instead pass typed conditioning inputs and keep a "continuity memory" of how each shot ends ([MVAgent](https://arxiv.org/abs/2609.30609)). ViMax (Jun 2026) models shots as a dependency graph and adds a VLM-based QC agent ([ViMax](https://arxiv.org/abs/2606.07649)). The practical design follows from this. Build a canonical character sheet once. Compose each shot's keyframe with a multi-image reference editor. Then animate between keyframes, so identity is re-anchored at every shot boundary. That avoids last-frame chaining, where errors and color drift build up after two or three hops.

For keyframes, **Qwen-Image-Edit-2511** is the strongest open option. Its model card says character consistency is "significantly improved" over 2509, and it can merge two separate people into one group shot ([HF model card](https://huggingface.co/Qwen/Qwen-Image-Edit-2511)). Community workflows take the face from one reference, the wardrobe from a second and the scene from a third ([Civitai](https://civitai.com/articles/29885/combine-multiple-reference-images-into-one-edit-with-qwen-image-edit-2511-lightning)). Among face-ID adapters on Flux, InfiniteYou edges out PuLID-FLUX on identity loss (0.209 vs 0.225), and the authors call the Flux IP-Adapter weak on faces ([InfiniteYou](https://arxiv.org/html/2503.16418v1)). Reference editors like Nano Banana Pro and Qwen-Edit preserve identity well but struggle with expression changes, a real limit for dialogue shots ([PixelSmile](https://arxiv.org/html/2603.25728v1)). For video, **Wan 2.2 (Jul 2025, Apache 2.0) is still the newest downloadable Wan**. Its add-ons Wan-Animate-2 and Wan-Dancer are open, but Wan 2.5 through 3.0 are API-only ([howaiworks.ai](https://howaiworks.ai/blog/alibaba-wan-open-weights-stopped-at-2-2)). That matches Mage's catalog, which lists "Wan Video v2.2". **LTX-2** (open since Jan 2026) generates video and audio together in one pass ([GlobeNewswire](https://www.globenewswire.com/news-release/2026/01/06/3213304/0/en/lightricks-open-sources-ltx-2-the-first-production-ready-audio-and-video-generation-model-with-truly-open-weights.html)). One licensing trap: MiniMax H3's community license bars local deployment in the US, EU, UK and South Korea without written authorization ([howaiworks.ai](https://howaiworks.ai/blog/alibaba-wan-open-weights-stopped-at-2-2)), so leave it out of a US-hosted project. For talking shots, LatentSync 1.6 re-lips existing footage, and InfiniteTalk (Wan-based, Apache 2.0) handles audio-driven body motion ([Instavar](https://instavar.com/research/ai-video/open-source-lip-sync-models)). Modal ships an official Chatterbox TTS example ([Modal](https://modal.com/docs/examples/chatterbox_tts)).

Speed and cost depend most on step distillation. LightX2V's Wan 2.2 distill LoRAs cut **40–50 CFG steps to 4 steps without CFG, about 20–24× fewer DiT evaluations** ([LightX2V docs](https://lightx2v-en.readthedocs.io/en/latest/method_tutorials/step_distill.html)). The catch is that **distillation can degrade identity**: character LoRAs and distill LoRAs interfere with each other ([DART](https://arxiv.org/pdf/2609.20051)), and few-step models weaken face preservation ([FastFace](https://arxiv.org/pdf/2505.21144)). "Distilled vs full steps, scored on ArcFace" is therefore exactly the kind of A/B test the CEO described. On Modal, the standard pattern is: weights in a Volume, `@app.cls(gpu=...)` per model family with `@modal.enter()` loading the model once, and a separate CPU FastAPI app (`@modal.asgi_app()` plus `@modal.concurrent`) that scales independently ([Modal SD example](https://modal.com/docs/examples/text_to_image)). **Memory snapshots** cut cold starts 3–10×, with GPU snapshots still in alpha. They don't speed up reading weights from storage. They conflict with multi-GPU code and sometimes with `torch.compile`. Redeploys invalidate them. Randomness seeded before the snapshot repeats on every restore, so reseed per request ([Modal docs: Memory Snapshots](https://modal.com/docs/guide/memory-snapshots)). Modal's own Wan2.1 face-LoRA example fans generation out over 7 H100s and renders a 30 s video in about 5 minutes ([Modal example](https://modal.com/docs/examples/music-video-gen)). H100s run about **$3.95/hr** and A100-80GBs about $2.50/hr ([Spheron](https://www.spheron.network/blog/modal-gpu-pricing-2026-per-second-billing/)). At those rates, the notes estimate that a 4-step FP8 Wan clip costs roughly $0.07–0.20 against $1–2+ undistilled. This is an unverified estimate, and benchmarking it yourself would make a strong piece of the project. Modal's examples index lists no official ComfyUI example ([Modal examples](https://modal.com/docs/examples)). A community repo shows ComfyUI on Modal with GPU snapshots and Wan 2.2 ([modal-comfyui](https://github.com/3kanAlpha/modal-comfyui)).

At the job level, production teams use durable execution. HeyGen runs millions of video workflows on Temporal and calls video generation "an orchestration problem as much as a media-processing problem". It also notes that per-customer fairness remains application logic ([Temporal blog: HeyGen](https://temporal.io/blog/how-temporal-powers-workflows-at-heygen)). Durable execution means a failure in the final step retries only that step ([GMI Cloud](https://www.gmicloud.ai/en/blog/temporal-cloud-continuous-ai-workflows)). Lighter engines like Inngest and Hatchet, or about 150 lines of hand-rolled step persistence ([HackerNoon](https://hackernoon.com/you-dont-need-temporal-yet-durable-execution-for-ai-agents-in-150-lines)), cover most of what a side project needs.

## Build "Castbook": a versioned, identity-gated shot pipeline on Modal

The recommended project is a small but production-shaped service, called Castbook here. It takes a **Character** (portrait → generated multi-view sheet → mean ArcFace embedding, plus an optional voice reference) and a short script. It returns a stitched 20–40 s multi-shot video. Each run follows a **workflow**: an immutable, versioned DAG config naming the model, revision and parameters for each step. The design draws on every section above. It copies Mage's own API shape, so Hunkins sees his own design choices reflected back. It routes around the Character/First-Last-Frame exclusivity by baking identity into keyframes and then using FLF interpolation. It addresses the Story Studio caveat about long sequences by measuring and enforcing consistency per shot. And it builds the feature no competitor documents: checking output quality and retrying when it falls short.

| JD requirement | What Castbook demonstrates |
|---|---|
| Clean API design, FastAPI | `POST /v1/characters`, `POST /v1/workflows/{id}/runs` returning `request_id` / `status_url` / `cancel_url`; idempotency keys; a per-run `billing` block of estimated vs actual GPU-seconds and $; OpenAPI docs; per-shot statuses so one failed shot never fails the job |
| Modal, GPU inference, cold starts, concurrency, autoscaling, cost | One `@app.cls` per model family sized to VRAM (Qwen-Edit on H100, Wan 2.2 FP8 + LightX2V on H100, InfiniteTalk/LatentSync on L40S, InsightFace/DINOv2 judge on a small GPU); memory snapshots with measured before/after cold starts; `max_containers` spend caps; a published table of p50/p95 latency and $/accepted-second |
| Google Cloud | Content-addressed artifacts in GCS: `key = sha256(step, model@revision, params, input hashes, seed)`; job and step state in Postgres (Cloud SQL or Neon); skip-if-exists gives free resume and cheap single-shot edits |
| Continuous integration of open-weights and third-party models | A `ModelAdapter` interface (capabilities: max refs, supports FLF, max duration, audio) with adapters for Qwen-Image-Edit-2511, Flux 2 or Kontext, Wan 2.2 I2V/FLF2V, LTX-2, plus one paid API (Nano Banana or a hosted video API) behind the same schema; a GitHub Actions job that runs a golden character × prompt set on every new adapter and fails if ArcFace p10 or latency regresses |
| Orchestration with retries, moderation, error handling | A CPU orchestrator that walks the DAG with `.spawn()` fan-out; Modal retries for transient errors, backoff for API 429/5xx, OOM fallback to lower resolution; three moderation gates (prompt, reference upload with a consent attestation plus a minor/NSFW classifier, final frames); an identity gate that re-rolls a shot up to N times when ArcFace min or p10 falls below a calibrated threshold, with every attempt logged |
| "Chain workflows to produce videos and test different variants" | The A/B harness: run the same script and character through 2–3 workflow versions (e.g., distilled vs full-step Wan, last-frame chaining vs keyframe-first FLF, open model vs paid API). Shared upstream artifacts are reused through the cache, and a report compares identity score, VLM-judge rubric, cost and latency side by side |

The A/B harness is the core of the project because it is the work Mage described. Version every workflow config so a single flag assigns arms. Freeze an eval set of about 5 characters × 10 shot specs. Report **$ per accepted second of video**, where "accepted" means the shot passed the identity and moderation gates. That metric joins quality and GPU cost, and with Gem-refund and "unlimited" economics, GPU cost decides margin. Avoid three traps. Don't build a node canvas UI; a plain HTML viewer of runs and scores is enough. Don't chase SOTA video quality. And don't use real people's faces in the demo: use generated characters, in keeping with Mage's own likeness rules. The ArcFace threshold has no published value for generated content, so calibrate it on a small hand-labeled set and show the calibration curve ([arXiv 2607.25622](https://arxiv.org/html/2607.25622v1) explains why face-only scores miss outfit drift, so add a DINOv2 whole-body score too). Scope it in tiers. The first tier is a working DAG with keyframes, I2V, the identity gate, stitching and the API, and should take roughly one to two focused weeks. The second adds the A/B report and model-onboarding CI. The third adds snapshots, cost dashboards, TTS and lip-sync. The first two tiers alone answer the CEO's description of the job.

## Conclusion

Mage's success with Characters creates an infrastructure debt that the product doesn't show. A face-only, single-portrait reference has to survive about 30 models with different reference caps, mode exclusivities and filters. A model release lands almost weekly. Unlimited tiers mean every unusable output costs Mage GPU time it isn't paid for. Competitors face the same problem, and every one of them has answered with more creative surface (canvases, agents, apps) rather than with measurement. The engineer who closes that gap will make identity a number, make workflows versioned and comparable, and make model onboarding a tested adapter instead of a bespoke integration.
